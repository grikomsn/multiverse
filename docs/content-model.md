# Content model

Sanity project `lboasusv`, dataset `production` (public; see the privacy note in AGENTS.md). Source: `packages/sanity/src/schema`.

## Principles

- One model, many sites: shared documents carry no per-site presentation fields. Site-specific settings live in that site's `site` document; layout lives in code.
- References over copies: career entries point at `organization`, links point at documents so slug changes propagate.
- Drafts are Sanity drafts. Published-but-hidden is `visibility: "unlisted"` (replaces Bear Blog's `discoverable`).
- Resume-style dates use `partialDate` (`YYYY`, `YYYY-MM`, `YYYY-MM-DD`). Talks use a real `date`.
- Drag-and-drop ordering (`orderRank`) for career lists; no hidden `sortOrder` numbers.
- A fact lives in one field. Text that would repeat one (a role in a description, a profile link in a page) is built from that field in code, or by a block such as `profileLinks`.
- Where data came from is recorded under Migration sources, not on each document.

A link in rich text points at a post or page by reference (`internal`) or at a URL (`href`). Queries turn a reference into `/<slug>` (`https://nibras.co/<slug>` in the archive), so renderers only see `href`.

## Redirects

Sanity has no redirect type. Each address has one owner:

- **Old addresses of a post or page** are its `aliases`. `apps/web/src/pages/[file].ts` writes one `_redirects` rule for each, so a redirect follows a later slug change.
- **Paths that no document owns** (old feeds, `/articles`, `/projects`, pages that live only in the archive) are rules in the same file. `/schedule` goes to `profile.scheduleUrl`.
- **nbr.st short links** live in the KV namespace that the nbr.st Worker reads (`apps/links`, see [apps/links.md](apps/links.md)), and nowhere else. Sanity held a copy until 2026-11-22; no code read it, and the public dataset let anyone list it.

## Project metrics

A project's `repositories` and `packages` say where usage numbers come from: every repository adds its GitHub stars, npm packages their downloads and VS Code extensions their installs. The first repository is also the source link. `PROJECT_SOURCES` (`packages/content/src/fragments.ts`) turns them into the `repoUrl` and `metrics` shape that pages read. `apps/web/src/lib/metrics.ts` reads the numbers when the site builds (stars through `@multiverse/content/github`, installs, and a year of weekly npm downloads for the sparklines), so they are never stored in Sanity. A failed request shows no number and does not fail the build. Set `GITHUB_TOKEN` in the build environment to avoid GitHub's limit of 60 requests an hour.
