# Rebuilding an archive edition

Playbook for rebuilding one past version of the site in `apps/archive`. v4 is the reference implementation.

Stack: this repo (Bun 1.4.4 + Turbo monorepo, Astro 7.4, Sanity project lboasusv/production). Several editions can be rebuilt at the same time in the same `apps/archive` app. Keep each rebuild inside its own files (see the lane rules below).

Context: archive.nibras.co hosts every past version ("edition") of Griko Nibras's personal site, rebuilt with its ORIGINAL look and showing TODAY's content (since 2026-11-21; see docs/redesign.md, "How the archive shows current content"). Read first: AGENTS.md, docs/legacy/README.md (decisions + architecture), the per-version research report(s) named below in docs/legacy/, packages/sanity/src/schema/documents/edition.ts (the `edition` document: meta, screenshots and design `assets`), and the finished reference implementation of v4:

- settings apps/archive/src/editions/v4/live.ts (page headings, intro sentence pattern, profile groups) and the adapter apps/archive/src/lib/live.ts
- app code apps/archive/src/editions/v4/* and routes apps/archive/src/pages/v4/_, shared shell apps/archive/src/shell/_ (ArchiveBanner + ArchiveHead must be on every page), queries in apps/archive/src/lib/queries.ts (EDITION_QUERY) and helpers in apps/archive/src/lib/editions.ts.
  Original sources: zips in `tmp/multiverse-<ver>.zip` (gitignored; extract them into a temporary folder outside the repo, never into it), a local checkout of the 2023a and 2023b repos (their GitHub remotes no longer exist; read them only, and run no git command that changes them), Wayback captures (curl https://web.archive.org/web/<timestamp>id_/<url> gives raw HTML; CDX API https://web.archive.org/cdx/search/cdx?url=...&output=json). Content in Sanity: posts are `post` docs with ids like post-<slug> (bodies shared with the current site).

For EACH edition in your list:

1. Write apps/archive/src/editions/<key>/live.ts: each page's heading and description in the version's own words (keep original wording, typos included), and its intro in its own sentence pattern filled with current facts. Facts never come from the period. Upload design-only images (wordmarks, textures, favicons) to the edition's `assets`. Set status "inProgress" while working and "rebuilt" (or keep "reconstruction" for v5) when the rebuild is done.
2. Rebuild the look in apps/archive/src/editions/<key>/ + apps/archive/src/pages/<key>/**, matching the original's CSS framework/version, fonts, layout, colors, signature interactions (small vanilla JS or Astro islands are fine; no React/Next runtime unless truly unavoidable). Each edition's CSS must be imported only by its own layout. If the edition used Tailwind, use a separate entry CSS with `@import "tailwindcss" source(none); @source "../editions/<key>";` (Tailwind 4 syntax; emulate v1-era utilities where they differ) or vendor the original compiled CSS. Internal links must be prefixed with /<key>. Blog post pages: render the shared `post` bodies with the edition's own typography. Each edition needs its own <key>/404.astro.
3. Screenshots for tracking (the archive index shows edition.screenshots[0]): with a browser (use your own tab if other rebuilds share the browser) capture (a) the original via its Wayback URL at 1280x800 and (b) your rebuild from the archive dev server at http://localhost:4322/<key>/ (start it with `cd apps/archive && bunx astro dev --port 4322` if it is not running; leave it running, because other rebuilds use it). Upload both PNGs to Sanity and set edition.screenshots = [rebuild, original] with alt text saying which is which (use apps/studio/scripts/editions/screenshots.ts). If Wayback is unavailable for an edition, skip (a).
   Lane rules (important):

- Edit only: apps/archive/src/editions/<your keys>/**, apps/archive/src/pages/<your keys>/**, apps/studio/scripts/editions/<your keys>*.ts. You MAY append new projections to LIVE_SITE_QUERY (packages/content/src/live.ts) only if today's data lacks fields you need — prefer not to; re-read right before any edit and keep edits minimal and additive. Do NOT edit other files under packages/**, root package.json, turbo.jsonc, other editions' folders, or the archive index.
- Dependencies (e.g. bulma@0.7.2, @fontsource/*): add exact versions released at least two weeks earlier to apps/archive/package.json. Read the file again just before you edit it and only insert lines, because other rebuilds can edit it at the same time. Then run `bun install` from the root. Report every dep you added. Paid/licensed fonts (e.g. Berkeley Mono) must be swapped for free equivalents.
- Sanity writes: only edition-<your keys> documents and image assets. Never modify or create other documents (posts, projects…); list such needs in your report (e.g. a post that only existed in an old version).
- Never copy secrets/tokens/.env from old sources; the v2 build and v6 .env.example are known to contain leaked credentials — don't transcribe them. Don't add analytics, comments, service workers or dead third parties.
- Verify: `cd apps/archive && bunx astro check && bunx eslint . && bunx astro build` pass (another rebuild's unfinished files can break the build: if an error is clearly in another lane, note it and leave it). Close the tabs you opened. Do not commit or push; the person who started the rebuild reviews and commits.
  Report, per edition: routes rebuilt, fidelity notes (what matches, what differs), design assets uploaded, screenshot asset ids, dependencies added, and items that need work outside your lane.
